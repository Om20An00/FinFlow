Idempotent payments

Sends the same payment twice with the same Idempotency-Key. Money moves once.

Concurrent transfers

Fires 6 parallel payments from one wallet. Optimistic locking + retries keep the balance exact.

Rate limiting

Bursts 30 payment reads through the gateway. The Redis token bucket answers 429.

Poison message → DLQ

A note with #poison makes the notification consumer fail, retry 3× then dead-letter.

Authorization (RBAC)

Calls an ADMIN endpoint with your token. Customers receive 403, admins succeed.

Security: no token

Calls the API without a JWT and with a tampered one. Both get 401.

Engineering highlights

            
    
              
  • Keycloak OIDC, Authorization Code + PKCE, realm roles → Spring Security authorities
    • 
              
  • Every service re-validates the JWT (defence in depth)
    • 
              
  • gRPC for internal calls, REST at the edge, deadlines + correlation-id metadata
    • 
              
  • Transactional outbox with FOR UPDATE SKIP LOCKED relay
    • 
              
  • Idempotency: Redis fast path + unique DB constraint + idempotent gRPC + idempotent consumers
    • 
              
  • Optimistic locking (@Version) with bounded retries
    • 
              
  • Kafka manual ack, retry, dead-letter topics, consumer groups
    • 
              
  • Database per service, Flyway migrations
    • 
              
  • Micrometer → Prometheus → Grafana, correlation ids across HTTP/gRPC/Kafka
